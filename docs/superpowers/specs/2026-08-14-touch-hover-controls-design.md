# 触屏上「看不见但点得着」的四个悬浮控件(回溯审计 E1)

## 一、问题

`.code-run`(代码块右上角的「运行」)是 `opacity: 0` + `.code-wrap:hover` 才显形。
触屏设备**没有 hover** —— 手指按下去浏览器可能合成一次 hover,也可能不,不能指望。

回溯审计的实测(iPhone 13 视口):

```
opacity           0
pointer-events    auto          ← 看不见，但点得着
命中区            73 × 21 px    ← 盖在代码块的横向滚动区上
```

**后果**:想左右滑动看长代码行,手指落在那 73×21 上 —— **静默启动一条命令**。
而 `.code-run` 是整个预览/执行功能的**唯一入口**,手机上等于这个功能不存在。

### 不止一个控件

全仓 `opacity: 0` + hover 显形的一共**四处**(`styles.css`):

| 行 | 控件 | 干什么 | 误触后果 |
|---|---|---|---|
| 253 | `.code-copy` / `.code-run` | 复制代码 / **跑一条命令** | **执行命令** |
| 52 | `.session-del` | 删会话 | 弹确认框(有二次确认,轻) |
| 166 | `.msg-revert` | 回滚到这条消息 | **回滚工作区**(本仓 CLAUDE.md 专门记过这个坑) |
| 170 | `.msg-copy` | 复制消息 | 轻 |

审计只点了 `.code-run`,但**病因完全相同**,而 `.msg-revert` 的后果同样重
(它会回滚工作区、抹掉未提交的改动)。一次修就该四个一起修 ——
只修一个等于留着三个同型缺陷,下次审计再发现一遍。

## 二、方案:两条独立的修,分别管两种设备

### 2.1 触屏/无 hover 设备:让它们**看得见**

```css
@media (hover: none) {
  .session-del, .msg-revert, .msg-copy, .code-copy, .code-run { opacity: 1; }
}
```

**判据用 `(hover: none)` 而不是 `(pointer: coarse)`。** 两者常被混用,但语义不同:
`pointer: coarse` 说的是「主指点设备不精确」(触屏、电视遥控、Wii 手柄),
`hover: none` 说的正是「**主输入方式无法 hover**」—— 而这里坏掉的恰恰是 hover。
带触屏的笔记本(Surface)是 `hover: hover` + `pointer: fine`,鼠标在场,不该被改。

### 2.2 有 hover 的设备:隐藏时**不该点得着**

```css
.session-del, .msg-revert, .msg-copy, .code-copy, .code-run { pointer-events: none; }
/* 显形的那些选择器里同时恢复 pointer-events: auto */
```

即使有鼠标,`opacity: 0` 的东西仍然拦截点击 —— 这本身就是错的:
淡出动画那 150ms 里点下去照样触发,而用户看到的是一个正在消失的按钮。
**「看不见的东西不该能被点」是一条独立于触屏的正确性**,不能只在触屏上修。

`:focus-visible` 那条显形分支不受影响:键盘焦点不经过 pointer-events。

### 2.3 为什么不做「点一下先显形、再点一下才触发」

那是很多站点在触屏上的做法,但:
- 要写 JS 状态,四个控件各写一遍;
- 破坏键盘/读屏的语义(一个按钮变成两态);
- 而它换来的好处(少占视觉空间)在这里不值 —— 这几个控件本来就在角落里。

**取舍:触屏上常驻可见,视觉上会比现在"吵"一点。** 这是故意付的代价 ——
换的是「唯一入口在手机上不再隐形」和「不再误触发命令/回滚」。

## 三、落地范围

只改 `packages/web/src/styles.css`。不动任何 TSX —— 这是一个纯样式缺陷。

## 四、测试点

CSS 没法靠单测锁住(jsdom 不做媒体查询求值、也不算视觉)。所以:

1. **真浏览器 + 触屏模拟**(playwright,`hasTouch: true` + iPhone 视口):
   - `.code-run` 的 `opacity` 必须是 `1`;
   - 它必须**真的可见**(`boundingBox` 非空且面积 > 0)。
2. **真浏览器 + 桌面视口**:`.code-run` 初始 `opacity: 0` 且
   `pointer-events: none`;hover 到 `.code-wrap` 之后两者都恢复。
3. **静态守卫(可单测)**:`styles.css` 里,凡是出现在那份「悬浮控件」名单里的选择器,
   必须同时被 `@media (hover: none)` 块覆盖。
   —— 这条防的是「以后新增第五个悬浮控件、又忘了加进媒体查询」。
   它**锁的是文件内容**,是弱测试,但比没有强;真正的验收在第 1、2 条。

**变异验证**:删掉 `@media (hover: none)` 块 → 第 1 条必须红。
