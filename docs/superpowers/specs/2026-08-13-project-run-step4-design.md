# 代码执行 步骤 4 设计：在项目里真跑命令

> 上游：`2026-08-11-code-exec-runner-v4-design.md` §11 第 4 步、
> `2026-08-12-code-exec-step3-design.md`（步骤 3，已合入）。
>
> 用户原话触发的这一步：「**如果我 edit 了代码中的一部分，我是不是可以继续点运行按钮，
> 运行整个项目？**」

---

## 0. 实测事实

### 0.1 `PROJECT_POLICY` 承诺的三条都成立（此前零调用点、零真跑）

`probe-step4-project.mts`，真进程：

```
① 唯一订阅者断开后 status=running        ← 片段档这里会 exited/detach
② 重连拿回 70 字符历史，且之后继续收新输出
③ reg.stop() → exited / reason=killed
④ 对照组：同一条命令在片段档注入 400ms 墙钟 → reason=wall-clock；
   项目档同期仍 running（没有被墙钟波及）
⑤ 刷屏 3 万行 → reason=exit（不是 output-cap）—— 环形缓冲真的不杀
⑥ 本仓根 package.json 有 10 条 script：dev/build/start/lint/format/…
```

第 ④ 条的对照组是必要的：只断言「项目档没被杀」证明不了「墙钟没装」——
也可能是墙钟压根坏了。片段档同期被砍，才说明机制活着而项目档确实豁免。

### 0.2 竞品：「点按钮跑项目」是标配，不是差异化（有引用）

| 工具 | 点按钮跑项目 | 依据 |
|---|---|---|
| Cursor | ✅ | 官方文档：main 方法上方的 Run 链接；Run and Debug 侧栏 |
| Windsurf（已改名 Devin Desktop） | ✅ | 官方文档明写 `tasks.json` + `launch.json` + `Ctrl/⌘+Shift+B` + F5 |
| Zed | ✅ | `.zed/tasks.json` + 行内 play 按钮（runnable indicators） |
| JetBrains | ✅ 最强 | package.json 侧边栏直接跑 script |
| Claude Code Desktop | ✅ 仅 dev server | 会话工具栏 server 下拉，`.claude/launch.json` |
| VS Code | ✅ | tasks.json 自动检测 npm |

**所以「别的工具不行」不成立**，这条不能作为立项理由。

**真正少见的是这个组合**：跑在**你本机的真实项目**上 + 用户点击驱动 +
**和一个读同一份文件的 agent 共处一个界面**。（Replit/Bolt/v0 在云容器里，不是你的机器；
Claude Code CLI 没有按钮。）

顺带一条对步骤 5 的输入：**编辑聊天代码块 + 跑编辑后的版本**，Cursor/Windsurf/Zed/JetBrains
四家**都没有**；ChatGPT 有且文档化了「编辑会进入上下文」；Claude Artifacts 文档化了
**不会**进入。**Zed 做过又删了**（`0.231.1`，2026-04-08：Removed legacy Text Threads）。

*方法学*：Cursor/Windsurf/Zed/JetBrains 那批是直接抓官方文档 + URL；OpenAI 那条因
`help.openai.com` 返回 403，是搜索工具读取官方帮助页，未亲眼看原始 HTML。

### 0.3 未实测

- HTTP/1.1 每域名 6 连接对同时看多个 run 的实际影响（浏览器侧，需真浏览器）
- 非 Windows 平台

## 1. 范围

**做**：
1. 项目档接线（选档规则）
2. 命名脚本按钮（读当前 cwd 的 `package.json` scripts）+ 自由命令框
3. 命令的同意缓存（键含 cwd）
4. 在飞运行列表（第三个 store）

**不做**：
- **PTY / stdin**（见 §7.1，这是个硬限制，必须写进面向用户的说明）
- 聊天代码块就地编辑（见 §7.2，**明确决定不做**）
- 把 run 暴露成模型工具（步骤 5）

---

## 2. 选档规则：按请求形态选，**绝不加客户端 `policy` 字段**

```
POST /api/runs
  { exec: {kind, code} }   → 片段档 SNIPPET_POLICY   （有墙钟、断连就杀、超预算就杀）
  { command: "..." }       → 项目档 PROJECT_POLICY   （无墙钟、断连保留、环形缓冲不杀）
```

**为什么不让客户端传 `policy`**：那等于任何客户端都能给**任意命令**要来
「无墙钟 + 断连不杀」——一个永远跑着、没人看着、没有上限的进程。
档位是服务端按请求形态推导的结论，不是客户端的输入。

现状是 `server.ts:1018` 写死 `() => SNIPPET_POLICY`，改成按形态选。

**代价**：以后若真需要「用命令形态跑一条短命令」，没有办法要片段档。
接受——短命令跑完就退出了，项目档对它没有坏处（无墙钟只对不退出的进程有意义）。

## 3. 命名脚本按钮

### 3.1 数据来源

`GET /api/scripts?sessionId=…` → 服务端读**当前会话 cwd** 下的 `package.json`：

```json
{ "cwd": "E:/proj-a", "scripts": [{ "name": "dev", "command": "vite" }, …] }
```

第一版**只读 `package.json`**。pyproject / Makefile 留到以后——
每加一种格式就是一套解析 + 一套坑，先把最常见的那种做对。

### 3.2 **cwd 是活的，列表必须跟着重取**

本仓会话 cwd 会被 `applyCapturedCwd` 改（模型 `cd` 之后持久生效）。
脚本列表若只在挂载时取一次，模型 `cd ../other-project` 之后，
**按钮上写着 A 项目的脚本、跑的是 B 项目**。

做法：cwd 变化时重取。cwd 通过现有的 session state 推送到前端（已有通道）。

### 3.3 **脚本白名单是便利，不是安全边界**

`scripts.dev` 完全可以是 `rm -rf /`。所以：

- 命令正文**照样过** `hasBlockingBashSecurityIssue` 确认闸
- 照样走 §4 的同意缓存
- **不因为「它来自 package.json」豁免任何一条**

按钮省掉的是「记不住命令」，不是「不知道要跑什么」。

---

## 4. 同意缓存（命令版）

键 = `sha256(cwd + '\0' + command)`，与步骤 3 的 `consentKey` **同一个函数**
（那个函数签名就是 `(cwd, code)`，逐字复用）。

**这一步正式兑现 v4 §9**：cwd 必须进键，否则模型 `cd ../other-project` 之后，
同一条 `python check.py` 命中同意缓存、**跑的是另一个项目里的那个文件**，不再询问。

**推翻记录**：`runsRoutes.ts` 的注释写着「不做同意缓存……属于步骤 4」——
现在就是步骤 4，那句注释要改掉。

**已知代价**：命令里带时间戳/变量 → 每次都问。不缓解，写下来。

---

## 5. 在飞运行列表（第三个 store）

`activeExec.ts` 是单槽，它自己的注释写着「真到了三个槽再说」——就是现在。

- **后端不用新写**：`GET /api/runs` → `runs.list()` 已有；DELETE 停止已有
- 前端：一个 `runningList` store，轮询 `GET /api/runs`（不是每个都开 SSE，见 §6）
- UI：右栏一行 chip，点一个 → 那个成为「聚焦的 run」→ 只有它开 SSE

**没有这个列表，步骤 2 承诺的「可重连」在前端不可达**——这是 v4 §7 的原话。

---

## 6. SSE 连接预算

HTTP/1.1 每域名 6 连接，而 `maxConcurrent: 8`。`streamRun` 的注释自己承认过
「本步只有片段档、同时最多 1 个，不构成问题」——项目档会撞。

**做法：只给聚焦的那个 run 开 SSE，其余靠轮询 `GET /api/runs` 看状态。**
代价：非聚焦的 run 看不到实时输出（切过去时靠 replay 补历史，历史在环形缓冲里）。

## 7. 明确不做

### 7.1 不是终端：没有 PTY、没有 stdin

`proc/spawn.ts` 是 `stdio: [opts.stdin ?? 'ignore', 'pipe', 'pipe']`，
而 `startServer.ts` 的 spawn 只传 `{cwd, env}` → **stdin 恒为 ignore**。

所以这是「**跑 + 看 + 停**」，不是终端：
- 要按键、要回答 `y/N`、要 Ctrl+C 交互的命令**驱动不了**
- 没有 PTY 意味着有些工具会关掉颜色/进度条（这对我们反而是好事，见 v4 §8）

**这条必须写进面向用户的说明**，否则用户会当成终端用然后卡住。

### 7.2 聊天代码块就地编辑：**决定不做**

用户问题的另一半。三条理由：

1. **它答不了用户的问题。** 片段跑在临时目录里现写的 `main.py`，项目根本没参与。
   「改一段聊天里的代码」和「跑整个项目」在机制上是两件不相干的事。
2. **它一行就能做通，正因如此危险。** `activeExec` 已经是「点运行那一刻冻结的快照」，
   换成编辑后的 buffer 是改一行。但**模型永远看不到编辑后的版本，而且没有任何机制能改**——
   protocol 里没有改写既有消息的 op（只有整回合 revert）。编辑会**静默生效**，
   记录里还是旧代码，界面上没有任何信号。它还叠在「模型看不到运行输出」之上，
   故障链是：改了模型看不见的代码 → 跑出模型看不见的报错 → 问「为什么报错」→ 模型对着旧代码猜。
3. **Files 面板已经把「改代码」解决得更好**：`writeFile` 真写盘、带 mtime 冲突守卫，
   **而且改动落盘 = 模型下一轮读得到**。文件是双方共同的真相。

**替代**：代码块上加「**写入文件…**」（复用 Files 面板那条 writeFile 链）。
改动落盘 → 模型可见 → 然后点脚本按钮跑项目。这条路把用户想要的两半接上了，
而且没有真相分歧。

*旁证*：Zed 早期的 Text Threads 就是「整个对话是可编辑 buffer」，
`0.231.1`（2026-04-08）把它删了。有人走过这条路又退回来。

## 8. 取舍

1. **模型仍然看不到运行输出**（步骤 5 才解决）。
2. **不是终端**（§7.1）。
3. **非聚焦的 run 没有实时输出**（§6）。
4. **daemon 被强杀时留孤儿 —— 本步必须解决，不能推后（这条是评审推翻我之后重写的）。**

   我原来写的是「片段档有墙钟兜底、项目档没有，所以是新风险，缓解留到以后」。
   **「墙钟兜底」是错的**：墙钟是 daemon **进程内**的 `setTimeout`（`run.ts:127`），
   `taskkill /F` 干掉 daemon 的同时也干掉了这个定时器，孙进程照跑。实测复现：

   ```
   父=40384  shell包装=33756
   只杀父进程（等价于 taskkill /F 不带 /T）
     杀后 1s: 1786582461659
     杀后 4s: 1786582464736     ← 心跳仍在推进，孙进程活着
   ```

   **所以两档在 daemon 被强杀时同样留孤儿，这不是本步引入的新风险，而是一直就有、
   只是片段档跑得短没人注意。**

   **而且它不是边角路径**：本仓 `.claude/skills/restart` 每次重启 daemon 用的就是
   不带 `/T` 的 `taskkill`，而 `startServer.ts` 自己的注释写着「本仓每次改 web 都要重启 daemon」。
   「跑着 `pnpm dev` → `/restart` → 端口被一个找不到的进程占着」是开发主路径。

   **最小修复（已做）**：restart 技能的 `taskkill` 加 `/T`。一个字符。

   **另一个实测发现，比评审说的更严格**：`/T` **只在父进程还活着时有用**。
   父进程一死进程树就断了，事后再对那个 pid 跑 `taskkill /T` 得到的是
   `ERROR: The process not found`，而孤儿还在跑 —— 只能按命令行去
   `Get-CimInstance Win32_Process` 里捞。**所以是「杀之前必须带 /T」，不是「事后可以补」。**

   **评审顺带否掉了我原来的缓解方案**：「pid 落盘 + 启动时回收」有坑 ——
   落的是 `child.pid`，那是 cmd.exe 包装器（实测 33756），它先死、pid 可能被系统回收，
   重启时对它跑 `taskkill /T /F` 会**误杀无辜进程**。这条不能照做。

## 9. 测试要点

- 选档：`{command}` 拿到项目档、`{exec}` 拿到片段档；**客户端塞 `policy` 字段被无视**
  （变异验证：让它生效 → 这条必须变红）
- 同意：同一条命令第二次不问；**`cd` 之后重新问**（这是 v4 §9 的核心断言）
- 脚本列表：cwd 变了列表跟着变；没有 package.json 时不报错、给空列表
- 脚本白名单不豁免安全闸：让 `scripts.evil` = `echo $(whoami)`，必须仍然要确认
- 在飞列表：起两个 run，列表两条；停掉一个，列表跟着变
- **真跑验证**：起一个真的 `pnpm dev`，关掉页面（断连），确认它**还活着**；
  重连拿回历史；点停止真的停
- **真浏览器点一遍**（步骤 3 欠着的那条，这步一起补）

## 10. 落地顺序

1. 选档规则（服务端，一处 + 测试）
2. `GET /api/scripts`（读 package.json）+ cwd 变化重取
3. 命令的同意缓存（复用 `consentKey`）+ 改掉 `runsRoutes.ts` 里那句过时注释
4. 在飞运行列表 store + 右栏 chip
5. 自由命令输入框
6. 代码块「写入文件…」（§7.2 的替代方案）
7. rebuild + 重启 + **真浏览器点一遍**
8. 合本地 master + 写 `docs/features.md`
